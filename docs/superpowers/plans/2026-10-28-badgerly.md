# Badgerly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser app that makes a badge or placard (shape, inset border, Google Font text, graphics) and exports a layered SVG for a laser or a watertight STL for a 3D printer.

**Architecture:** Everything is a polygon set in millimeters (Clipper2 integers at 1/1000 mm): shapes, borders, shaped text, and uploaded SVGs all go through one `Poly` type, so the same unions and offsets serve the laser export, the 2D stage, and a 2.5D mesh builder that constructs STL caps, walls, and fillet lofts without 3D booleans. The React app is Kerfuffle's shell (app bar, stage, numbered inspector) with Badgerly's sections and a full Google Fonts picker.

**Tech Stack:** Vite 6, React 18, TypeScript 5, Vitest 3, `clipper2-js`, `harfbuzzjs`, `earcut`, `three`, `lucide-react`, `@fontsource-variable/figtree` and `bricolage-grotesque`.

**Spec:** `docs/superpowers/specs/2026-10-28-badgerly-design.md` (shape reference: `docs/superpowers/specs/die-cut-shapes.png`; corner art reference: `docs/superpowers/specs/border-corner-art-reference.png`).

## Global Constraints

- Internal unit is millimeters everywhere; the display unit is `'mm' | 'in'` and defaults to `'in'`.
- Preview curve tolerance 0.05 mm; export tolerance 0.01 mm; fillet facets step at most 0.02 mm.
- Clipper integer scale: 1000 units per mm. Polygons use Clipper orientation: outer contours have positive area, holes negative.
- Badge coordinates: origin at the badge center, x right, y down.
- Laser SVG: 1:1 mm, `viewBox` in mm, cut stroke `#ff0000`, score stroke `#0000ff`, engrave fill `#000000`, stroke width 0.1, every piece in a named `<g>`.
- STL: binary, millimeters, watertight, plate flat on the bed (z = 0 is the bed).
- Multi-color split defaults: recess 0.6 mm, clearance 0.1 mm. Default plate 3 mm, fillet 1 mm, emboss 1 mm.
- Border scores when its style is single, dashed, or corners and its width is at most 0.5 mm; otherwise it engraves. (My refinement of the spec's rule; a 0.5 mm line is one laser pass.)
- Nudge: 0.1 mm per arrow key, ten times that with Shift. Snap threshold 6 screen pixels.
- Stacked layout gap 5 mm; SVG margin 1 mm.
- Copy and labels follow the Google developer style: sentence case, second person, no exclamation marks.
- Commit after every task with a one-line imperative subject and the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. Text containing a character the font lacks (an emoji): the element is skipped with a `missingFont` warning naming the character, nothing throws. Test in Task 9.
2. A corner radius, chamfer, or cutout larger than half the short side: `clampShape` limits it and the shape stays a simple polygon. Test in Task 3.
3. A border inset deeper than the shape allows (the inward offset vanishes): the border is empty and a `borderTooDeep` warning is raised, nothing throws. Test in Task 5.
4. A deboss deeper than the plate, or a fillet larger than the shape allows: clamped, reported with `clamped: true` in the result, and the mesh is still closed. Test in Task 14.
5. An uploaded SVG that only has strokes, or has nested transforms: the stroke-only file gives an empty polygon and a `strokeOnlySvg` warning; the transforms are applied in order. Test in Task 4.

  ```ts

  export function clampRelief(relief: ReliefConfig, outline: Poly): ReliefConfig;  // edgeMm ≤ min(bounds)/2 − 0.5 and ≤ plateMm − 0.4

With `split`, the recess is `offset(emboss ∪, clearanceMm)` debossed by `recessMm`, and `parts` is each emboss poly extruded from 0 to `recessMm + mm` at the same x and y.
